Comprendre le service

Demande de paiement
Identifiée par la clé d'idempotence de l'appelant (Booking ou Access). Porte le statut final et regroupe 1 à N transactions.

Transaction
Une tentative d'encaissement (UUID v7). Reste PENDING pendant le délai d'attente, puis ACCEPTED ou REFUSED.

Retry automatique
Un refus ouvre une seule transaction supplémentaire. Si elle échoue aussi, la demande passe à REFUSED.

Opérations
POST /payments crée (202) ou rejoue (200) ; GET /payments/{id} donne le résultat ; la page interroge la liste toutes les 2 s. API complète : /docs.
